# Production Checklist

Use this before running the agent for a real store and team. Credentials alone are not enough — complete every section.

## Deployment tiers

| Tier | Description | Minimum requirements |
|------|-------------|----------------------|
| **Pilot** | Small team, read-only, one channel | Sections 1–4 |
| **Production** | Daily ops, trusted team | Sections 1–6 |
| **Write-enabled** | Discounts, inventory, fulfillments | All sections + team training |

---

## 1. One-time setup

```bash
npm install
npm run setup              # Shopify + Discord → config/.env
npm run discord:demo-setup # optional: lock bot to #store-ops
```

- [ ] `config/.env` exists and is **not** committed to git
- [ ] Shopify connection verified during setup (or mock mode chosen intentionally)
- [ ] `DISCORD_ALLOWED_CHANNEL_IDS` set to your ops channel only

## 2. n8n workflow (one-time, persists in Docker volume)

- [ ] Import `n8n-workflows/discord-shopify-mcp-agent.docker.json`
- [ ] Google Vertex credential added to **Google Vertex Chat Model** node
- [ ] GCP project ID set in Chat Model node
- [ ] Workflow toggled **Active**
- [ ] Test execution visible in n8n **Executions** tab

Vertex credentials persist in the `n8n_data` Docker volume. Avoid `docker compose down -v` unless you intend to reset n8n.

## 3. Start and verify the stack

```bash
npm run docker:up
npm run verify:production
```

- [ ] `docker compose ps` — all services healthy
- [ ] `curl http://localhost:3000/health` — returns `"status":"ok"` and your shop domain
- [ ] `docker compose logs bridge` — shows `Discord bridge online`
- [ ] Test message in Discord returns a real reply

## 4. Security defaults (pilot minimum)

```env
SHOPIFY_READ_ONLY=true
DISCORD_ALLOWED_CHANNEL_IDS=your_channel_id
```

- [ ] Read-only mode enabled for initial rollout
- [ ] Bot limited to one (or few) known channels
- [ ] n8n UI (`:5678`) **not** exposed to the public internet
- [ ] Discord + Shopify tokens stored only in `config/.env`

## 5. Public / remote deployment

Required if using **n8n Cloud** or exposing MCP outside Docker network:

- [ ] MCP served over **HTTPS** (reverse proxy, Railway, Fly.io, or Cloudflare Tunnel)
- [ ] `MCP_API_KEY` set in `config/.env` (auto-generated by `npm run setup`)
- [ ] n8n **Shopify MCP Tool** node updated with public SSE URL
- [ ] Configure MCP auth in n8n if exposing MCP publicly (match `MCP_API_KEY`)
- [ ] `N8N_WEBHOOK_URL` on bridge points to your n8n instance production webhook

## 6. Write-enabled production (optional)

Only after read-only pilot is stable:

```env
SHOPIFY_READ_ONLY=false
```

- [ ] Team trained on `CONFIRM <token>` flow for inventory, fulfillments, refunds
- [ ] Only trusted staff in the allowed Discord channel
- [ ] Shopify custom app has minimum required write scopes
- [ ] Monitor `docker compose logs mcp bridge` during first write operations

## Ongoing operations

| Task | Frequency |
|------|-----------|
| Check `docker compose ps` | Daily (or use host monitoring) |
| Review n8n execution errors | Weekly |
| Rotate Discord/Shopify tokens if leaked | Immediately |
| Backup `n8n_data` volume | Weekly |
| Review Vertex AI usage/costs | Monthly |

## Backup n8n data

```bash
docker run --rm -v shopify-discord-agent_n8n_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/n8n-backup.tar.gz -C /data .
```

Replace volume name with output of `docker volume ls | grep n8n`.

## What is NOT production-ready out of the box

- Multi-store / multi-tenant hosting
- Per-user Discord permission checks (anyone in the channel can query)
- High-availability or auto-failover
- Webhook HMAC signing (keep n8n on private network)
- CONFIRM tokens survive MCP restarts (in-memory, 5 min TTL)
